# 未知 Modbus 設備唯讀探索

## 不可違反的規則

1. **只允許 FC03 與 FC04**。不得自動執行任何寫入（FC05／06／15／16），也不要建議「寫寫看」。
2. 掃描前先問使用者：設備是否在運轉中、是否接在現場生產線。老舊 RS485 設備大量連續讀取可能當機，先用小區塊、低頻率。
3. 原始回應、解碼結果、用途推測**分開顯示**，不得把推測寫成確定名稱。
4. 推測必須標示信心與依據。
5. 至少取樣兩次（中間讓現場狀態改變，例如開關負載），用變化判斷哪些是即時量測。
6. 掃描結果完整匯出，不能只保留畫面上的前幾筆。
7. 使用者確認前，探索結果不得覆蓋任何既有的原廠設備模板。

## 掃描建議（用使用者自己的唯讀工具執行）

- 區塊讀取：一次 1～120 個暫存器可調；某區塊逾時或回例外時，**二分**縮小範圍找出有效位置，不要一個個硬掃整個 0～65535。
- 例外碼 02（非法位址）是正常結果，記錄後跳過。
- 每個有效位置第二次取樣後再比對。
- 常見起點：0～200、1000～1200、4096 附近、30001／40001 換算後的 0 附近。

## 離線解碼

```bash
python scripts/decode_candidates.py 掃描結果.csv -o 候選.csv
```

輸入欄位：`fc,address,sample1,sample2[,sample3...]`（範例 `examples/示範掃描結果.csv`，虛構數值）。

輸出每個位址：原始值（十進位＋十六進位）、是否變化、解碼候選（uint16／int16 × 1、0.1、0.01、0.001；相鄰兩格的 float32、uint32 × ABCD／CDAB／BADC／DCBA）、推測理由、信心、狀態固定為「候選（未驗證）」。

- 倍率候選只用縮小（1、0.1、0.01、0.001），避免放大倍率造成誤判。
- float32 只列合理範圍（有限值且 1e-4～1e7）。

## 交給 AI 判讀時

送給模型的資料要包含：設備類型、站號、功能碼、位址、原始值、至少兩次樣本、候選解碼、現場人員輸入的已知變化（例如「14:02 開了一台冷氣」）。
模型回覆必須包含：候選用途、單位、信心、理由、**下一個驗證動作**。AI 只讀探索結果，不得呼叫任何 Modbus 寫入。

## 產出

探索結果整理成位置表草稿後，交給 `modbus-sitemap-tw` 的逐點確認流程，確認完才算正式位置表。
