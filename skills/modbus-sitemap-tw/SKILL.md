# 台灣 Modbus 位置表 → tag map

## 什麼時候用

- 使用者拿到廠商手冊或 Excel 的位置表，要匯入監控軟體、資料收集器或 Modbus MCP。
- 讀值「差 1 格」、浮點數很怪、倍率不對、負數變成 6 萬多。
- 要把一份位置表整理成可以交給程式讀的格式。

## 安全原則

1. 這個 skill 的工具**只處理檔案**，不連任何設備。
2. 轉出來的結果一律是「候選」，必須逐點確認後才能上線（見下方流程）。
3. 不要替使用者猜缺漏的欄位：型別、字序、倍率、功能碼沒寫就標「待確認」，不要填預設值後當成確定。
4. 廠商手冊有版權，不要把整份原廠位置表貼到公開地方；範例一律用自己做的虛構資料。

## 位址規則（最常出錯）

| 手冊寫法 | 功能碼 | 封包位址（0 起算） |
|---|---|---|
| 40001 / 400001 | FC03 holding | 0 |
| 40100 | FC03 holding | 99 |
| 30001 / 300001 | FC04 input | 0 |
| 10001 | FC02 discrete | 0 |
| 00001 | FC01 coil | 0 |
| 0x1000 | 看功能碼欄 | 4096 |
| 465537 | — | 不合法（超過 65535） |

- 同一份表**混用**參考位址和 0 起算時，不要自動猜，整份停下來問使用者要用哪一種（腳本 `--address-mode`）。
- Excel 會把 `00001` 顯示成 `1`：要保留參考位址，儲存格要存成文字。
- 功能碼欄和位址前綴衝突（例如寫 FC04 但位址是 4xxxx）時列為錯誤。

## 型別與字序

- 16 位元：`uint16`／`int16`。溫度、功率因數、雙向電力可能是負值，要用 `int16`。
- 32 位元（float32／int32／uint32）佔 2 個暫存器，64 位元佔 4 個。
- 字序：`ABCD`（big／big）、`CDAB`（字組對調，台灣許多電表常見）、`BADC`、`DCBA`。手冊沒寫就標待確認，用實機讀值比對面板數字決定。
- 倍率寫法都要收：`0.01`、`×0.01`、`1/100`、`1e-2`。倍率 0 是錯誤，不是空白。

## 工具

```bash
python scripts/sitemap_to_tagmap.py 位置表.csv --check            # 只檢核
python scripts/sitemap_to_tagmap.py 位置表.csv -o 設備.tags.json
python scripts/sitemap_to_tagmap.py 位置表.csv --address-mode reference
```

- 只用 Python 標準函式庫；CSV 可為 UTF-8、CP950、Big5。
- 欄位名稱中英文、全形半形都收（例如「位址／地址／暫存器」、「倍率／係數」、「站號／設備位址」）。
- 會檢查：名稱重複、位址超界、同站號同區塊重疊、coil 帶型別、倍率為 0。
- 會提醒：32／64 位元沒寫字序、有倍率沒型別、數值點沒單位。
- 輸出格式相容 IndustriAgents/MODBUS-MCP 的 `REGISTER_MAP_FILE`。

範例：`examples/示範位置表.csv`（虛構設備）。

## 逐點確認流程（上線前必做）

1. 先決定整份表的位址寫法（參考位址或 0 起算），切換寫法時所有確認歸零。
2. 每一點確認：名稱、功能碼、封包位址、型別、字序、倍率、單位、讀寫。單位空白要明確勾「確認無單位」。
3. 任何欄位被修改，該點的確認就撤銷。
4. 設備資訊（站號、鮑率、同位、停止位元、IP）一開始全部空白，不套任何設備的預設值。
5. 全部啟用點都確認、設備資訊完整、填了確認者，才產生正式設備檔；保留來源（檔名、頁碼或工作表、原始列文字）方便日後對照手冊。
6. 用唯讀方式（FC03／FC04）實機試讀，跟設備面板比對至少 3 個數值，再交給畫面使用。

## 回報格式

回報每個點時附：名稱、功能碼、封包位址、原始暫存器值、換算後數值與單位、判斷依據；不確定的寫「待確認」和下一步怎麼驗證。
